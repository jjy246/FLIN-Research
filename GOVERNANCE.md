# FLIN Community Governance

FLIN is currently **maintainer-led**. The project founder/maintainer owns the
official GitHub repository and makes final decisions about source merges,
version tags, official Releases and which network snapshots receive an official
reviewed listing. This does not restrict anyone's rights to fork the
Apache-2.0 source or publish their own lawful adaptations and data.

## How decisions work

1. Anyone can propose a bug fix, documentation change or research hypothesis in
   an Issue, or submit a Pull Request.
2. Maintainers ask for a clear description, reproducible steps and tests as
   appropriate; theoretical disagreements can remain open without forcing
   artificial consensus.
3. At least one maintainer reviews each proposed merge. Automated checks inform
   but do not replace review. The maintainer may accept, request changes,
   decline, or redirect domain-specific changes to a fork.
4. Official software releases are distinguished from network-data Releases by
   tags: `vX.Y.Z` vs `network-*` / `community-*`.
5. Community networks require the separate process in
   [docs/COMMUNITY_NETWORKS.md](docs/COMMUNITY_NETWORKS.md), including rights,
   format checks and real import testing. Acceptance is **not validation of
   mathematical truth or neuroscientific accuracy**.

## Public discussions and conflicts

Report bugs and debate implementation trade-offs in public Issues unless the
content includes security vulnerabilities or private material. The maintainer
may close spam, abusive conduct, non-actionable requests or repeated submissions.
Appeals/reconsideration may be requested on the original Issue, with new data.

## Future stewardship

As participation grows, maintainers can publish a transparent review roster and
merge policy. No project member receives maintainer access merely for submitting
an interesting network. Software remains forkable under Apache-2.0.
